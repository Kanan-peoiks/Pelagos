# SeaSentry API

Real backend for the SeaSentry frontend: user auth and incident data, replacing
`lib/auth.ts`'s localStorage mock and `lib/mock-data.ts`'s static incidents.
Built with FastAPI. Deployed separately from the Next.js frontend (which stays
on Vercel) — see **Deploying to Render** below for why.

The `/detect` endpoint is a placeholder for the ML teammate's oil-spill model
— see `app/routers/detect.py` for the expected shape.

## Local setup

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS/Linux
pip install -r requirements.txt
cp .env.example .env          # defaults to a local SQLite file, no DB setup needed
python -m app.seed            # optional: adds 2 demo incidents
uvicorn app.main:app --reload
```

API docs (Swagger UI) are then at `http://localhost:8000/docs`.

## Endpoints

| Method | Path | Auth | Description |
| --- | --- | --- | --- |
| POST | `/auth/register` | — | Create a user, returns a JWT |
| POST | `/auth/login` | — | Returns a JWT |
| GET | `/auth/me` | Bearer | Current user |
| GET | `/incidents` | — | List all incidents |
| GET | `/incidents/{id}` | — | One incident |
| POST | `/incidents` | Bearer | Register a new detection |
| POST | `/incidents/{id}/decision` | Bearer | Confirm / reject / escalate / mark cleaning — mirrors `applyActionToIncident()` in `lib/incident-store.tsx` |
| POST | `/detect` | — | **Stub** — 501 until the ML model is wired in |
| GET | `/health` | — | Render health check |

Response JSON uses the same camelCase field names as `lib/types.ts`'s
`Incident` type (e.g. `areaM2`, `aiProbability`, `displayId`), so swapping the
frontend from mock data to this API shouldn't require renaming fields.

## Deploying to Render

Vercel (where the frontend lives) only runs short-lived serverless functions —
no persistent Python process, tight package-size limits that libraries like
this API's dependencies (or a future ML model's) can exceed. So the API
deploys as its own service on Render instead, and the frontend calls it over
HTTPS.

1. Push this repo to GitHub (already done) and connect it in the Render
   dashboard → **New → Blueprint**, pointing at `backend/render.yaml`.
2. Render will create the `seasentry-api` web service. Before the first
   deploy succeeds, set these env vars in the Render dashboard (they're
   marked `sync: false` in render.yaml, meaning Render won't auto-fill them):
   - `DATABASE_URL` — a Postgres connection string (e.g. from Supabase or
     Neon's free tier, or Render's own free Postgres add-on). Without this,
     the service falls back to SQLite on Render's ephemeral disk, which is
     wiped on every redeploy — fine for a quick test, not for real data.
   - `CORS_ORIGINS` — your Vercel URL(s), comma-separated (e.g.
     `https://your-app.vercel.app,http://localhost:3000`).
   - `JWT_SECRET` is auto-generated by the blueprint (`generateValue: true`);
     leave it as-is.
3. After the first deploy, run the seed script once from Render's shell (or
   locally against the same `DATABASE_URL`) if you want demo data:
   `python -m app.seed`.

**Free-tier heads up:** Render's free web services spin down after 15
minutes idle and take ~30-50s to wake on the next request. Fine for
development; for a live demo, hit `/health` a minute before you go on to
warm it up, or upgrade the plan.

### Frontend wiring (not done yet)

Don't call this API directly from the browser. Add a Next.js server-side env
var (e.g. `BACKEND_URL`) and proxy through Next.js Route Handlers — the same
pattern already used in `app/api/copernicus-token/route.ts` — so the browser
only ever talks to Vercel, never to Render directly. This sidesteps CORS
entirely and keeps the backend URL out of client-side code.
